# 夸克连接的验证步骤

[接入方案](QUARK-AUTH-RESEARCH.md) · [文档目录](README.md)

验证分为独立运行、真实授权、目录完整性和收藏关联四关。每一关单独记录结果；工具能运行、流程显示绿色、测试数据通过，都不等于账号连接已完成。

## 第一关：无账号的独立运行检查

仓库提供 `scripts/probe-quark-runtime.mjs`。它复制官方CLI到本次独立目录，使用空HOME/USERPROFILE，不继承Codex、DSH等Agent环境变量，依次调用：

```text
--version
--help
resolve-agent
```

报告只保留版本、退出码、错误分类等白名单字段，不上传CLI原始日志或配置；结束后清理本次运行时目录。不调用login、logout、用户信息、网盘读取或写入操作，不使用已有账号。

本地复现（先取得可信官方工具）：

```powershell
node scripts/probe-quark-runtime.mjs "C:\path\to\quark-drive.cjs"
```

GitHub Actions也提供手动触发的 [Quark Windows compatibility probe](../.github/workflows/quark-preflight.yml)。它下载固定1.0.25分发包，保留TLS校验，并与本次审阅时固定的SHA-256比对后执行。包改变就停止，不能自动更新校验值来绕过检查。

**判断标准**：版本和帮助必须正常，独立环境身份识别也要通过。出现 `-104` 则说明当前分发工具不能原样运行于这个独立环境，先解决受支持的应用身份/适配方式，不能靠注入其他Agent的标识把检查变绿。`resolve-agent`成功仍不等于账号授权或目录功能已通过。

诊断流程允许记录已知的“不支持”结果后正常结束；因此GitHub流程本身成功只代表报告生成完成，实际兼容结论以报告的`outcome`为准。

## 第二关：本机真实授权

仅在第一关及官方支持的接入方式明确后进行。需要用户在自己的Windows电脑上完成浏览器授权，不能在云端用他人的账号或模拟响应替代。

1. 应用/受支持的官方工具发起一次`login`，浏览器正常打开。
2. 用户核对官方授权页与权限，完成授权。授权码和Token不发送到聊天、GitHub、日志或测试报告。
3. 授权任务得到真实成功结果，再调用`get-user-info`确认实际账号；`-118`等“已有有效授权”结果单独处理。
4. 退出并重启，仍能识别同一账号并读取目录。
5. 分别验证取消、超时、网络失败和过期；不能把网络故障直接当成账号退出，也不能无限重试登录。

**通过标准**：界面账号来自真实接口，凭据保存成功，重启可用，失败/取消不会显示假成功。此过程不是导入用户的现有Agent配置，也不保证官方授予了目录级最小权限。

## 第三关：指定文件夹完整读取

选择用户已有的小测试目录，或由用户自行准备；应用不自动向网盘上传测试文件。

检查超过5个文件、至少一个子目录、中文文件名及电影/剧集命名。与夸克客户端中的文件名和数量核对，验证完整分页、递归范围、重复读取去重和中途取消。结果应来自完整artifact，不是预览列表。失败不能替换同一账号/范围的上次成功清单；换账号必须隔离旧缓存。

**通过标准**：只读取选定范围，文件集合与实际目录一致，重复扫描不增加重复项；没有发生上传、改名、移动、下载或分享。

## 第四关：收藏关联

待匹配与关联功能实现后，检查同一剧集多集归并、同一作品多版本、同名不同年份作品、TMDB歧义确认和重复同步。保留个人评分/短评/专题，不因网络失败或远端文件缺失而删除收藏，不伪造分享链接。

只有四关都通过，才称为“自动读取夸克指定文件夹并整理成影视收藏”。前三关通过只证明账号与资源清单接入。
