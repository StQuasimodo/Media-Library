# TV 云端进度备份与迁移

开发预览 `0.3.0-alpha.9` / versionCode17。补齐 alpha.7/8 云端试播进度未进入备份的缺口，保留原文件与每个云端版本的独立时间轴，不改变播放器内核或电影取流方式。

## 用户行为

设置中的本机备份、文档导出、下载目录导出、恢复前备份与更新前备份现在覆盖：收藏、媒体关联、原文件进度、云端播放进度。所有恢复入口先读取并校验文件，再说明覆盖范围，确认后执行。换电视仍需重新连接账号与选择网盘目录；不备份凭据或电影。

| 备份格式 | 恢复范围 | 本机云端进度 |
| --- | --- | --- |
| v1 | 仅收藏 | 保留 |
| v2 | 收藏、媒体关联、原文件进度 | 保留，确认框明确提示 |
| v3 | 收藏、媒体关联、两类进度 | 用备份内容替换，包括明确的空列表 |

v3需本版或更新兼容版本读取，旧版会拒绝未知格式。现有v1/v2文件和旧签名导出工具生成的v2文件继续可读。云端标识沿用原来的 `SHA256(mediaKey + NUL + selector)`，换设备后按相同媒体/版本找回时间；不会把不同版本或原文件的进度混在一起。

## 存储与事务

原云端进度位于 `cloud-hls-progress-v1` 偏好文件。它无法与两个SQLite库共同提交/回滚，因此本次新增独立 `cloud-playback.db`（schema1），只存哈希、position、duration。已有收藏库和 `media-sources.db` 的schema/version保持不变。

首次创建新库时在SQLiteOpenHelper创建事务中导入旧偏好记录；保留旧XML和其中原有字段。后续重开、恢复空列表不会再次导入并覆盖新数据。旧偏好不继续更新，降回旧程序不会看到后续新进度；不要把保留的XML当作持续同步副本。非法旧时间值会中止迁移并保留原数据，不静默清空；原文件播放不依赖云端库打开。

备份以 `ATTACH` 把三个持久SQLite库放入同一回滚日志事务，先保存完整恢复前副本，再替换相应内容；云端插入位于最后，以便真实验证晚期失败时三库一起回滚。沿用日志模式检查，拒绝WAL/内存日志等不支持既有联合恢复策略的状态。不承诺未测试的设备断电/文件系统故障行为。

`cloudProgress` 仅允许64位小写哈希和两个非负整数；拒绝重复、缺失、分数时间和超量记录，读/写时过滤未知云端字段。上限10000条、整个备份8MiB；超限拒绝导出，不截断本机历史。迁移本身不按备份条数截断。编码共享未更改的收藏结构，避免为新增云端字段复制整个收藏对象。

播放器退出销毁云端数据库句柄；进度写入失败时提示并保留此前数据。夸克Cookie、Token、临时CDN地址、环回密码和播放路由均不进入云端备份。此变更不增加电影磁盘缓存。
