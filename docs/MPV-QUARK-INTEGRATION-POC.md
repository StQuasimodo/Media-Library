# Test-only mpv and Quark relay integration

[API22 run 42634027977](https://github.com/StQuasimodo/Media-Library/actions/runs/42634027977), second attempt, passed against a controlled fixture. The first attempt failed before mpv was reached: a device rotation destroyed the media browser while the UI test still referenced it, causing a rejected executor task. This is retained as a test/lifecycle issue, not treated as an mpv failure.

The instrumentation APK only provisions the exact mpv-android backport debug APK from run 42583190460 (SHA-256 `743176933d593bbf7f10db084371ce4c07d4ce6eabeac3fd6b9958f4f478f6ee`); native libraries are extracted exclusively into the test APK. The production APK remains LibVLC-only. The JNI declaration follows mpv-android's bridge at commit `3018d47277d5b3ca02acdd96466f261c1d23ee08`; mpv-android and bundled mpv/FFmpeg dependencies have their own licenses and this experiment is not a redistribution or production dependency approval.

The test opens the existing `QuarkDavManager` scoped playback lease; mpv receives only its ephemeral loopback Authorization header, with native option logging suppressed before it is supplied. It loads an HTTPS-backed synthetic Quark fixture through the existing 127.0.0.1 relay and checks 1080p track dimensions, time advancement, pause, seek to 20 seconds, resume and HTTP 401 after session revocation. It uses mpv `vo=null` and `ao=null`: video rendering, sound output, subtitle presentation, real credentials, hardware decode/fallback, and the actual television are not established. The full existing LibVLC Quark 90-second playback, exact Range recovery, reconnect and collection regressions ran afterward and passed in the same API22 x86 emulator. ARMv7 libraries were packaged for the test but not executed.

Source, media and application settings are controlled fixtures; no real user's Cookie is passed to the decoder. The gateway session credential is short-lived and has only the selected file scope. The test does not demonstrate that every native logging path is safe for production; header/redirection handling, source rebuild and dependency pinning, ABI compatibility, UI lifecycle, track and subtitle controls, plus real-device and real-account tests remain mandatory before an integrated player can replace or accompany LibVLC.
