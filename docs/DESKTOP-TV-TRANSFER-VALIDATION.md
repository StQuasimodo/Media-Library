# 电脑到电视迁移交付记录

Windows 1.3.0-beta.7 与 TV 0.3.0-alpha.12 / code20 提供专用迁移。操作步骤见[迁移指南](DESKTOP-TV-TRANSFER.md)。

## 改动与数据保护

- 电脑生产导出服务在SQLite一致读事务中生成格式2 JSON，包含收藏、个人记录、专题、系列、分享资源及当前夸克连接中已知文件的关联／忽略；不包含凭据、设置、图片缓存或临时播放地址。
- 电视按稳定TMDB身份合并，电脑个人记录优先，保留TV独有作品和原文件／云端版本进度。恢复前安全副本与三库联合事务覆盖后期失败回滚；SQLite schema不变。
- 迁移关联等待原目录实际文件ID确认；改名不重配，暂时消失的忽略文件返回后保持忽略。后续电视手动操作优先，再次导入则应用导出文件中的选择。
- 可一次补全缺失图片；保留已有图片、个人记录和关联，连续三次失败暂停。电视继续使用自己的TMDB配置。
- 带扩展选择的TV备份为格式4，拒绝被旧格式读取器静默丢弃；新版读取已有格式1–3。

## TV API22 验证

源提交 `8153e9957b4df6c4b0d12f4fbd1147b119d47077`，[完整构建](https://github.com/StQuasimodo/Media-Library/actions/runs/44346285785)成功。迁移44项、完整功能225项、备份25项、覆盖升级12项通过，另有原生解码、夸克DAV／断流／HLS、遥控器、收藏、进程和设备重启回归。迁移专项直接读取桌面真实生产导出的同一fixture，包含原生确认／取消、主键复用、跨三库晚期失败回滚、凭据保留与批量补图检查。API21最低版本、v1签名、固定证书和ARMv7／x86库包检查通过。

首轮测试修正了“新导入季必须沿用电脑ID”的错误假设：真实合并应复用TV已有的同TMDB季身份，修正后的测试额外断言两集资源指向这个TV身份。后续测试依赖下载阻塞，改为有界下载并验证固定SHA-256的CI专用FFmpeg；不计为应用运行失败，也不把未执行记录作为通过。

## 验收边界

受控账号／协议与合成媒体测试不代表真实个人夸克账号。API22/x86模拟器不代替ARMv7长虹实机；4K原盘、HDR、硬解性能和真实账号链路仍待实机确认。播放器仍为LibVLC3.7.7，本次未改解码内核、双字幕或网盘取流。旧的普通JSON存档、SQLite备份不能当作本次专用迁移文件；未来新文件不继承旧FID的忽略选择。
