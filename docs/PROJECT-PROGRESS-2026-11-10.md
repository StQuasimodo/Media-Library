## 4. 内核与字幕决策

保留 LibVLC 作为当前生产路径，mpv 作为双字幕能力的主要候选。现有 LibVLC Java 接口只有单条 SPU 选择，无法直接交付主副双字幕；mpv 的 API22 x86 PoC 已支持继续评估集成，但尚未通过用户要求的 ARMv7 运行门禁。

不要将“换成 mpv”当作整套字幕功能已完成。当前双轨证据主要是 SRT/mov_text；ASS/SSA、外挂加载、PGS/VobSub、中文字体与乱码编码都需专门样片。独立字号目前主要有属性证据；两轨分别字体/颜色等选项需要核查候选版本及渲染结果，必要的内核补丁应独立评审。

新内核继续使用 `MediaTransfer` 与单文件会话，不向解码器传夸克 Cookie；外挂字幕须单独授权指定字幕文件，不能扩大成整目录权限。保留地址刷新/字节精确 Range/撤销/有限恢复，不增加全片下载或大型磁盘缓存。

## 5. 后续里程碑与验收门槛

建议按以下顺序推进。版本仅是建议，实际分发前按 [VERSIONING.md](VERSIONING.md) 核定，不预建 Tag 或覆盖旧包。

### M1：收敛现有播放开发，交付可升级预览（建议 alpha.5 / code8）

1. 先修浏览器销毁/请求取消和高置信度解析错误，增加对应真实网络与界面回归。
2. 恢复固定签名构建，完成可导出数据保护；验证从 alpha.3 覆盖升级后收藏、TMDB 配置保留，开发版原有媒体关联和进度也保留。
3. 将主线倍速/诊断纳入统一 API22 回归，提供版本、源码、哈希、签名一致的单 APK 与报告；回归覆盖 DAV 范围、取消、断流、定位、续播、进程/系统重启。

**出口**：用户可实际安装并找到媒体源/基础播放入口；明确标为开发预览，真实夸克扫码/长虹仍未验收时如实记录。此阶段不等待 PotPlayer 所有功能齐全，也不把 mpv 试验库先塞入发布包。

### M2：完成内核门禁，接入可选 mpv 与双字幕

1. 锁定原生构建、许可与长期产物来源；ARMv7/API22 至少完成 JNI 加载、H.264/AAC、双字幕、定位与暂停恢复。无 ARM 环境时保留未通过状态。
2. 在独立集成分支实现小范围播放器接口，隔离 VLCVideoLayout 与 mpv Surface；保留 LibVLC，处理音频焦点、Surface/Activity 生命周期、单实例原生上下文、退出回收和恢复设置。
3. 提供明确的主/副字幕选择与分别关闭、位置、字号、时间偏移；核实其余独立样式。加入同目录外挂字幕选择/自动建议及手动改选，先覆盖 SRT/ASS。

**出口**：同一个交付候选 APK 中可从真实界面操作，两轨画面和样式/偏移变化有视觉证据；字幕只获自身文件授权；原取流/收藏回归通过，长播与内存测试归属具体内核。没有这个闭环前不宣称 mpv 已集成完成。

### M3：解码、声音与 4K 能力分级验收

- 增加真实解码器/硬软路径、像素格式/位深、掉帧、缓冲与会话传输诊断；未知写未知。硬解初始化失败与播放中失败分别测试，回退有限次数且保留位置/暂停/轨道；网络故障不误判解码故障。
- 媒体矩阵覆盖 H.264、HEVC 8/10-bit、MPEG-2、VP9，AAC/AC3/EAC3/DTS、多字幕格式；4K 使用运动画面、正常帧率和代表性高码率片段，分别记录打开/解码/流畅/输出，不能只有分辨率与单帧证据。
- 获取长虹实机的芯片解码、持续网络吞吐、可听音频/同步、遥控器和持续播放记录；HDR、环绕/直通另验。没有设备时可继续实现和模拟器回归，实机验收保持待完成。

**出口**：给出“原画硬解可用 / 软解可用但性能受限 / 当前不可流畅”的具体组合。不能保证老电视运行所有 4K 原盘；云端转码仅在真实夸克能力确认后另立方案，不默认已有。

### M4：补齐高频播放体验

按“可定位时间轴与精确跳转 → 按集/版本分组和返回焦点 → 上下集与自动连播 → 章节/书签/A-B → 逐帧与比例/缩放/裁切/旋转 → 均衡器/其他输出模式”拆小批交付。字幕编码、字体和图像字幕矩阵随 M2/M3 继续完善，不以更换内核代替功能验收。

Windows 保持独立稳定线。后续先做解析样本一致性与真实账号/升级验收，再评估图片手选锁定、缺横图时竖海报回退和不同缩放的视觉修整；保留现有 PS5 横向轨道、焦点联动及电影杂志方向，不重建数据库或前端。
