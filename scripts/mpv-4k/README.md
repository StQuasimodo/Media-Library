# API22 mpv 4K HEVC and decoder initialization fallback

This independent experiment uses the exact standalone mpv-android debug APK from [build 42583190460](https://github.com/StQuasimodo/Media-Library/actions/runs/42583190460), SHA-256 `743176933d593bbf7f10db084371ce4c07d4ce6eabeac3fd6b9958f4f478f6ee`. It is not integrated into My Cinema. The APK and upstream components' distribution and licensing must be reviewed before any release.

[Run 42629980590](https://github.com/StQuasimodo/Media-Library/actions/runs/42629980590) passed on an Android 5.1/API22 x86 emulator (1.5 GiB memory). Two locally generated monochrome 3840x2160 HEVC files, each 15 seconds at 5 fps, were decoded and produced PNG frames; input/output pixel formats identified 8-bit `yuv420p` and 10-bit `yuv420p10`. `hwdec=mediacodec`, `hwdec-codecs=all` and `hwdec-software-fallback=1` were requested. For each file the log recorded an attempt to initialize the HEVC MediaCodec path, `Could not create device`, and `Using software decoding`. The test checks these log lines and the decoded format, rather than accepting the setting alone.

This demonstrates recovery when hardware initialization failed in this emulator. It does not demonstrate fallback after a hardware decoder starts and subsequently fails, nor a real TV's hardware decode. The samples have a static image, low frame rate and low bitrate: they are not UHD Blu-ray, HDR, a cloud stream, or evidence of 4K real-time performance. Outputs are RGB captures, not HDR/display validation. Source archive and hashes, synthetic samples, logs, output and test results are retained in the `mpv-api22-4k-experiment` workflow artifact.
