# My Cinema TV 0.2.0-alpha.4（开发中）

播放器拆出独立PlaybackController，界面订阅连接/缓冲/播放/暂停/错误/结束状态；每次连接与播放会话各自拥有可取消的网络请求，重连保留位置和暂停意图，旧回调按会话丢弃。

本机WebDAV保留协议与目录职责，MediaTransfer负责驱动取流、临时地址、精确Range与有限断流恢复。参考TV Media的有界请求思路，夸克使用最多4MiB的顺序分段，64KiB流式拷贝，不增加大型预读缓存；支持尾部Range、HEAD经1字节GET探测，并核对首段和后续段的实际区间。每文件刷新锁合并同一过期地址的并发重取，Cookie在每次上游请求时读取当前值。播放器的独立本机鉴权在退出/重连时撤销并取消该会话的上游读取，其他会话保留。

借鉴源码和分工见[架构说明](TV-PLAYBACK-ARCHITECTURE.md)。继续使用Java、LibVLC3.7.7/OkHttp3.12、minSdk21及ARMv7/x86；没有引入完整OpenList、Node、Compose或新解码内核。Windows1.2.0、数据库schema、应用ID与开发签名不变。正在进行完整API22回归，真实夸克授权、服务端限速、实际提速和长虹硬解仍待验收，不把开源项目的测速当作本项目结果。

# My Cinema TV 0.2.0-alpha.3（开发中）

夸克内置播放直接连接本机WebDAV，去掉第二层转发；文件夹校验在后台线程执行。新增缓冲状态和保留进度的「重新连接」。网络缓存保持1.5秒，不以大幅占用老电视内存替代连接优化。

已开始输出的视频若中途断流，在同一响应内最多按字节续接两次；每次取流请求遇401/403仍最多刷新一次地址。续接必须返回精确Range、相同总长度及可用的ETag/Last-Modified标记，否则中止，已输出视频之后不追加HTTP错误页。[API22完整验证](TV-PLAYBACK-STABILITY-2026-10-28.md)已通过：原生解码、断流/过期、重连与90秒连续播放，以及收藏/进程/内核重启；真实夸克账号、旧WebView扫码、长虹硬解与整片长播仍待验收。Windows1.2.0、收藏schema和签名身份不变。

# My Cinema TV 0.2.0-alpha.2（开发中）

新增电视本机「夸克 → WebDAV」只读转换：账号连接后选择夸克文件夹，即可直接生成WebDAV影视源，用于目录浏览、扫描关联和内置播放。无需外部NAS/电脑或先填写已有服务。支持PROPFIND、GET/HEAD、Range与过期地址刷新；保留其他WebDAV客户端作为可选入口。

仅在本机提供服务，应用退到后台后停止；重新启动会生成新地址/密码，文件夹和基于文件ID的进度保留。不能将此开发实现当作真实夸克账号/旧WebView扫码或长虹实机硬解已验收。[本轮完整CI与API22界面/转换/播放/重启验证](TV-QUARK-WEBDAV-VALIDATION-2026-10-28.md)通过，最终构建源码为`9d33c9084633b8ac8c05984a0b185fbb08d4770f`；当前APK在Actions Artifact，尚未创建新Release。
